# Everyday Dialog gate

Chromium paired run passed **12/12** target executions for six everyday cases:
keyboard opening and initial input focus, Escape restoration, Close and reopen,
editing/submitting the form while staying open, background dismissal without
outside activation, disabled pointer dismissal, and cancellation of close requests.
The cancellation case observes request counts so unchanged open state is not an
unchecked pre-action snapshot.

The LiveView host uses native dialog modality plus mapped request policy. This
is a bounded comparison, not complete Base UI Dialog parity. Nested dialogs,
animations, alternate modality, touch screen readers and arbitrary initial/final
focus overrides were not part of this gate. Per user steering, verification was
Chromium only. Raw report: `artifacts/dialog-paired-chromium.json`.
